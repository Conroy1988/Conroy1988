## The builder

I am **Daniel Conroy**, an independent builder based in **Edinburgh, Scotland**.

I turn fragmented workflows into systems people can understand and trust: public products, deep game guides, browser tools, community automation, private intelligence platforms and the infrastructure underneath them. My work spans product direction, interface design, architecture, implementation, validation, deployment and live operation.

The domains change. The operating doctrine does not.

| Discover | Design |
| --- | --- |
| Map the real workflow, its evidence and its failure points. | Make complex state legible, responsive and worth using. |
| **Control** | **Operate** |
| Keep authority, safety boundaries and recovery visible. | Own the result after launch day—not just the first build. |

## 02 · MissionChief command suite

Three complementary products now cover the decision layer, the moving fleet and the incident map.

### [MissionChief Map Command Toolkit](https://github.com/Conroy1988/missionchief-toolkit-assets)

The Toolkit turns MissionChief's scattered signals into one responsive command environment: incident priority, fleet state, transport demand, map intelligence, resource pressure, financial reconciliation, diagnostics and safe recovery.

It keeps MissionChief authoritative. The product surfaces the signal, reaches the correct native control and fails closed when evidence is incomplete.

### [GitHub Achievement Encyclopedia](https://conroy1988.github.io/Achievements/)

An evidence-led reference that separates official documentation, reproduced behaviour, historical records, community claims and unknowns. Human-readable guides sit beside privacy-safe evidence records, verification timelines, bounded research tasks and a validated static API.

### [Auto Page Translator for Brave](https://github.com/Conroy1988/Brave-Auto-Page-Translator)

A privacy-conscious Manifest V3 extension for Brave and Chromium. It translates readable text inside the original page, preserves the real site's session and interactive state, and restores the original content in one action.

Manual/minimal-access mode is the default. Approved-site automation, per-site targets, live-page updates, glossaries and provider choices remain explicit and testable—with no analytics or developer-operated translation server.

### [Emby Best Episodes](https://github.com/Conroy1988/Emby-Best-Episodes)

An Emby Server plugin that builds best-rated playlists for each TV season without changing season order, episode metadata, ratings or watched state. It can rank one show, several selected shows or the full visible library, then refresh after scans or on a schedule.

## ConroyMedia

<img src="./assets/profile-operations-estate.webp" alt="A self-hosted operations environment with a server rack, service dashboards and Edinburgh at night" width="100%">

**ConroyMedia** is the live self-hosted environment where architecture meets operating reality.

It connects Docker services, Caddy routing, DDNS, media automation, service monitoring, Windows telemetry, GitHub Apps and isolated runners, Home Assistant integrations, deployment controls, backups and tested recovery paths.

```mermaid
flowchart LR
    Code[GitHub estate] --> Gate[Validation and releases]
    Gate --> Hub[TKB integration hub]
    Hub --> Community[Community systems]
    Hub --> Deploy[Production delivery]
    Services[Docker services] --> Observe[Monitoring and telemetry]
    Deploy --> Observe
    Observe --> Control[Authenticated control]
    Control --> Recover[Backup · restore · rollback]
```

> A system is not operational because it started once. It is operational when it can explain its state, limit its authority and survive failure.
